# Case study — a training provider makes its growth portable

*A training provider — a nursery (puukool) — drawn from real practice, told with
generic names so any provider or agent can see itself here.*

## The situation

A provider runs programmes made of courses, each with its own learning outcomes. It
carries more than one unit system at once — two definitions of a study hour plus
credit points — because different funders and regulators each expect their own. Its
offerings and records started scattered across spreadsheets, documents and old
software.

Much of the real work so far has been **quiet groundwork**: gathering, cleaning and
reconciling that data — from source registries, provider records and public data —
so it is accurate, consistent and up to date. This is the soil-tending nobody sees
but everything grows from, and it never stops: sources change, data drifts, it must
be kept fertile season after season.

## What was done

Once the ground was clean, each programme, course, outcome and credential is
*mapped* into CC's neutral slots — map, don't migrate; the internal system keeps its
own structure. Only the public, person-free description is projected at three seams:
the offering, the outcomes, the credential. Cohorts and participants stay private.

## What it unlocked

- **Portable growth.** A learner's credential now travels — the next organisation
  reads it and continues from the right place, instead of starting the person over.
- **Many gatekeepers, one fruit.** Because CC keeps both hour definitions and the
  credit value verbatim, one credential is readable by different funders at once —
  no one re-converts.
- **The validator guides the groundwork.** CC points at exactly which records are
  still incomplete — missing volume, missing outcomes — so the ongoing data-cleaning
  is guided, not guessed. The common language and the soil-work reinforce each other.
- **An agent as gardener.** An AI agent reads CC in no time, maps the offerings into
  the neutral slots, finds the gaps, and brings the system into order fast — then
  helps grow it.
- **The provider's own tree grows.** New programmes graft onto the same skeleton;
  the system grows organically instead of being rebuilt each time.

## What each reader gets

- **Agents & developers:** CC is the blueprint, the checklist and the guidance in
  one — adopt it instantly, organise a scattered or new system, and see what still
  needs cleaning.
- **Business:** less duplicated re-assessment, eligibility for more funders at once,
  and credentials that employers and clients trust because they are readable — resting
  on data that was actually cleaned, not just claimed.

*Edge this proves: the fruit is only trustworthy because the soil beneath it — the
ongoing data-cleaning — was tended. CC carries and guides the groundwork; it never
replaces it.*
